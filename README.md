# Operations-Manual-0

業務マニュアル 共有版

GitHubでコードを管理し、RenderのNode.js Web Serviceで実行する版です。
元のHTMLと `alpha/`、Sites用の `online-alpha/` は別に残してあります。

このGitHub配置用の版には、元の6件のサンプル業務手順を含めません。
マニュアル本文・画像・アカウント・バックアップはGitHubへ配置しません。

## 起動設定

画像改善版 v0.7.0 の保存・配信仕様とローカル検証結果をまとめています。
詳細は `IMAGE_IMPROVEMENTS.md` を参照してください。

- Runtime: Node.js 24
- Compute: `0.5c-512mb`（旧Starter）
- Persistent disk: 5GB / Mount path: `/var/data`
- Build command: `npm ci && npm test`
- Start command: `node server.mjs`
- Health check: `/health`
- `HOST=0.0.0.0`
- `MANUAL_HTTPS=1`
- `MANUAL_PREVIEW_MODE=0`
- `MANUAL_DATA_DIR=/var/data`
- `INITIAL_ADMIN_USERNAME=admin`
- `INITIAL_ADMIN_NAME=管理者`
- `INITIAL_ADMIN_PASSWORD`: Renderの環境変数で設定する8〜128文字の秘密値（既存配置の初期資格情報は維持）

DBが空のときだけ初期管理者を作成します。既存の管理者パスワードは上書きしません。
初期パスワードをソース、ログ、README、GitHubへ載せないでください。
ログイン用パスワードはRenderのEnvironment画面で確認します。

## 永続保存とバックアップ

公開環境は有料Computeと5GBの永続ディスクを使用します。
本文・画像・アカウント・更新履歴・サーバー内バックアップは `/var/data` に保存します。
画面名を「共有版」とし、無料の試験環境向けの消失警告は表示しません。
これは無停止運用・第三者による安全性評価・データ消失ゼロを保証するものではありません。

永続ディスクは通常の再起動・再配置後もマウント配下のデータを維持します。
誤削除・障害・サービスやディスクの削除等に備え、全体バックアップを別の保存先にも保管してください。
外部への自動退避は未設定です。同じディスク内のバックアップだけでは十分ではありません。

無料の使い捨て検証環境を別に作る場合だけ `MANUAL_PREVIEW_MODE=1` を設定し、
正式な資料を登録しないでください。有料化だけでは永続保存にならず、ディスクの接続と保存先の一致が必要です。

## ローカル確認

```text
npm ci
npm test
node server.mjs
```

初期管理者の環境変数なしでローカル起動すると、ループバック接続から初期設定できます。
公開環境で未設定の場合、インターネットからの初期登録は拒否します。

既存の検索・画像添付・お気に入り・管理・JSONバックアップに加え、
ログイン、4段階の権限、担当者、確認日、更新履歴、版の復元を備えます。
同時編集と全件復元は競合を拒否し、全件復元の途中で失敗しても元に戻します。

## アカウントと権限

- 一般ユーザー: 閲覧・検索
- 編集担当: 閲覧・追加・編集
- 資料管理者: 編集担当の操作、削除、旧版復元、資料のJSONバックアップ・復元
- システム管理者: 全操作、アカウント管理、SQLite全体バックアップ

管理者は「アカウント・権限」から氏名・ログインID・権限・利用状態を変更できます。
初期パスワードは半角英数字8文字で自動生成され、大文字・小文字を必ず含みます。作成直後だけ表示・コピーできます。
新規設定・変更・再設定は半角英数字8〜128文字、大文字・小文字がそれぞれ1文字以上必要です。
数字は使用可能ですが必須ではありません。大文字・小文字を区別し、空白・記号・全角文字は拒否します。
既存のパスワードは変更するまで引き続きログインに使用できます。
既存パスワードはハッシュのみを保存するため閲覧できません。
管理者は自動生成または手動入力でパスワードを再設定できます。
ID・権限・パスワード等を変更した利用者の既存セッションは失効します。
自分自身の管理者権限解除・利用停止は禁止します。

旧3段階DBは起動時に退避して4段階へ移行します。
再配置時の保守用 `POST /api/system-restore` は管理者認証とCSRF検証が必要です。
取得済みSQLiteバックアップを検証し、ユーザー・資料・版履歴をトランザクションで復元します。
復元前にも退避し、他のログインセッションは失効します。
